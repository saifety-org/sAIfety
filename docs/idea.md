# sAIfety — исходная идея и заметки

Это первоначальные заметки автора: назначение, требования и разбор угроз.
Реализация могла уйти вперёд; актуальное поведение смотри в [README](../README.md)
и [docs/configuration.md](configuration.md). Статус реализации — в [docs/status.md](status.md).

## Назначение 
инструмент предварительного анализа вводных данных

## Требования
- работа как MCP, агенты подключаются к MCP и она служит прокси для вводных данных (?)
- оффлайн анализатор, набор угроз и векторов анализа подготовлен и не подгружается в моменте

## Виды анализируемых угроз и способы обнаружения вредоносных данных
- context poisoning
  - разновидности отравлений контекста (?), как определить что контекст отравлен?
  - явные вредоносные инструкции 
    - удаление, 
    - зашифрованный, закодированные инструкции
    - любые не человеко понятные данные
    - вызовы внешних систем (curl, ssh, sftp, ftp ...)
    - переопределение инструкций
    - системные промпты

## Взаимодействие с агентом
разделить уровни угроз:
(какой кретерий для разделения?)
- базовый, предупреждение агента о сомнительном содержании проекта, данные эскейпятся, заворачиваются в блоки с предупреждением и инструкциями не выполнять этот код без явного подтверждения пользователя
- средний, источник данных содержит данные которые должны быть удалены до попадания агенту, например при работе с MCP в котором есть пользовательский ввод, сам источник доверенный, но данным нельзя доверять, все инструкции должны быть явно удалены,
- критичный, работа с источником останавливается, агент получает запрет на доступ к источнику без явного требования пользователя с ручным подтверждением

## Бизнес логика 
поиск инструкций и системных промптов (bert-like модели или чтото подобное, маленькая модель которая только ищет текст и может сказать является ли он инструкцией или нет)
поиск зашифрованных, закодированных данных, скриптов с закодированными данными, системных bash команд, анализ проводится итерационно: является ли команда вредоносной? если не является но она выполнима, и не требует внешних зависимостей что будет результатом ее выполнения, может ли это быть команда, если да является ли она вредоносной (итерация повторяется)

## Понятие угрозы
- Отправка данных пользователя во внешний источник (средний)
- удаление данных (средний)
- шифрование данных на устройстве (высокий)
- вывод чувствительных данных (высокий)
- установка компонентов (базовый)
- добавление новых репозиториев (или замена существующих) (высокий)
- добавление gpg ключей (средний)
- системные инструкции (высокий)
- установка сертификатов (высокий)
- выполнение произвольных команд (сильно зависит от типа команд, от базового до высокого)

## Дополнительный функционал
- обезличивание персональных данных (удаление ФИО из логов, или сочетания имени и номера телефона)
- маскирование IP адресов или названий сервисов
- удаление набора ключевых слов по списку
- удаление данных аутентификации и токенов
- белый список ключевых слов данные по которым должны остаться в выдаче
