# Сравнение классификаторов

`make compare` готовит выборки, обучает отдельного кандидата sAIfety,
запускает его вместе со встроенным классификатором и
`protectai/deberta-v3-base-prompt-injection-v2` на одних текстах и сохраняет
отчёт. Все шаги реализованы на Go. Нужны Go, C-компилятор
и локальный ONNX bundle, используемый приложением. Если модель отсутствует,
benchmark завершится с ошибкой: подменять DeBERTa лексическим fallback нельзя.

```sh
make build
make compare
```

Подготовка скачивает только JSON-данные из закреплённого коммита
[PIGuard](https://github.com/leolee99/PIGuard/tree/1b5751e88bf7475acbedfc8eda795ce060307c84/datasets)
и проверяет SHA256. Код из внешнего репозитория и тексты тестов не исполняются.
При наличии файлов в кэше весь эксперимент работает офлайн.

## Артефакты

Краткий итог этого запуска: [model-comparison-results.md](model-comparison-results.md).
Подробные артефакты находятся в `artifacts/comparison/` (каталог исключён из git):

- `weights.json` и `weights.json.meta.json`: новый кандидат, параметры обучения,
  хеш обучающего набора и хеш весов. Рабочий `internal/classifier/weights.json`
  автоматически не заменяется; обычная сборка приложения использует его.
- `train.jsonl`, `evaluation.jsonl`, `manifest.json`: точные выборки,
  разбиение, происхождение и контрольные суммы.
- `predictions.jsonl`: оценки трёх моделей, токены и задержка каждого примера.
- `predictions.jsonl.meta.json`: платформа, версии/хеши runtime и моделей,
  время загрузки, число исключений и ошибок.
- `report.json`, `REPORT.md`: итоговые метрики и срезы.

Можно повторить только расчёт отчёта: `go run ./cmd/comparison report`.
Модель и корпус связаны хешами; отчёт отклоняет несогласованные артефакты.

## Что делает сравнение честнее

1. **Сравниваются классификаторы.** Отчёт включает новый кандидат и
   встроенную production-модель рядом с DeBERTa. Никаких правил, декодера, маскирования,
   gate-классификатора или политики sAIfety в benchmark нет. Обе модели
   получают один и тот же исходный текст. Их собственные признаки и
   токенизаторы сохраняются.
2. **Внешний набор.** Используются BIPIA code/text, NotInject и benign-срез
   WildGuard, опубликованные авторами PIGuard. Их метки сохранены без изменений.
   Наш предыдущий синтетический регрессионный корпус сюда не включён.
3. **Защита от утечки.** Обучение использует существующие синтетические
   шаблоны, `external.jsonl`, `local_benign.jsonl`. Удаляются повторы и
   конфликтующие метки; строки, совпадающие с внешним набором точно или по
   Jaccard ≥ 0.8 символьных 5-грамм, исключаются из обучения. До сравнения
   применяется NFKC, case folding и сворачивание пробелов. Проверка не
   гарантирует обнаружение смысловых перефразировок.
4. **Разделение настройки и проверки.** Около 25% внешних групп служат
   калибровкой, остальные — тестом. Близкие варианты и варианты одной категории
   BIPIA остаются в одной части. Разделение определяется SHA256, до inference.
   Параметры обучения фиксированы: seed=1, 40 эпох, существующие признаки и
   DefaultTrain. После просмотра результатов модель не настраивается.
5. **Пороги.** Показываются 0.5 у обеих моделей и отдельно пороги, выбранные
   только на английской калибровке: максимум recall при эмпирическом FPR ≤ 1%.
   При равенстве предпочтительны меньший FPR и порог ближе к 0.5. Условие
   FPR на калибровке не гарантирует такой же FPR на тесте. Диагностически
   показывается 0.8 — порог детектора в приложении. Если приемлемый FPR
   достигается только отключением всех срабатываний, отчёт показывает это.
6. **Язык и контекстное окно.** Основной срез — English, NotInject Multilingual
   показан отдельно. По [карточке модели](https://huggingface.co/protectai/deberta-v3-base-prompt-injection-v2)
   DeBERTa предназначена для английских prompt injection; русский и jailbreak
   не являются её заявленной областью применения. Общий предел — 512 токенов
   DeBERTa вместе со служебными токенами. Подсчёт отключает скрытое усечение
   из `tokenizer.json`; слишком длинные тексты исключаются у обеих моделей.
7. **Метрики и скорость.** Считаются TP/FN/FP/TN, precision, recall, FPR, F1,
   balanced accuracy, AUROC, average precision. Для recall/FPR приведены
   интервалы Wilson. Парный bootstrap по группам даёт интервал разницы
   balanced accuracy при 0.5. CPU inference: batch=1, три прогрева, модели
   вызываются поочерёдно с чередованием порядка. Измеряется тёплый вызов с
   извлечением признаков/токенизацией; загрузка указана отдельно. Это не
   сравнение оптимизированных GPU- или пакетных реализаций.

## Почему старый benchmark был недостаточен

Раньше он случайно выделял 15% строк из `external.jsonl`, содержащего те же
источники, что и обучение sAIfety, без группировки дубликатов. DeBERTa также
указывает `jackhhao/jailbreak-classification` среди своих источников обучения.
Поэтому комментарий «DeBERTa не видела внешние данные» был неверен, а случайный
held-out из этого файла не давал независимой оценки обобщения.

Новый протокол проверяет известные обучающие данные нашей модели, но полный
обучающий корпус DeBERTa недоступен: отсутствие пересечений для неё доказать
нельзя. Нельзя также считать новый набор абсолютно нейтральным: его выбрали
авторы другой защитной модели. NotInject специально проверяет избыточные
блокировки, а BIPIA содержит инструкции, чья вредоносность зависит от
нахождения в недоверенном источнике. В отрыве от контекста некоторые из них
похожи на законные запросы пользователя. Результаты относятся к этому набору
и этим меткам, а не доказывают превосходство одной архитектуры вообще.

После использования набора для будущей настройки правил или модели он
становится набором разработки; следующая независимая оценка требует новых
данных. Не смешивайте этот результат с оценкой полного конвейера sAIfety.
